# Лабораторная работа №1 — RAG-ассистент по документам

**Дисциплина:** Системы искусственного интеллекта  
**Индивидуальный вариант:** базовый RAG по учебным материалам  
**Версия:** v1.0

Сервис ищет релевантные фрагменты локальных документов и возвращает ответ, составленный только из найденных фрагментов. Если релевантных фрагментов нет, возвращает `Не нашёл информации по вашему вопросу`.

## Стек

- Python 3.10+
- FastAPI + Uvicorn
- `sentence-transformers` — единая модель для индексации и запросов
- ChromaDB — постоянное векторное хранилище
- PyMuPDF / pypdf включены в зависимости для дальнейшего расширения; текущий учебный корпус — `.md` и `.txt`

## Корпус

В `data/` находятся шесть небольших демонстрационных документов на тему учебной библиотеки и работы с учебными материалами. Они созданы специально для лабораторной работы, не являются официальными правилами какого-либо учреждения и позволяют воспроизводимо проверить работу поиска.

## Установка и запуск

Python 3.10 или новее. Команды выполняются из корня проекта.

### 1. Создать виртуальное окружение

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
```

### 2. Установить зависимости

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

При первом запуске `sentence-transformers` скачает модель из Hugging Face. Для этого нужен доступ в интернет; после загрузки модель хранится в локальном кэше.

### 3. Построить индекс

```bash
python scripts/build_index.py
```

Скрипт читает `.txt` и `.md` из `data/`, делит тексты на чанки, считает эмбеддинги и пересоздаёт коллекцию ChromaDB в `.chroma/`. Повторный запуск перестраивает индекс с нуля.

### 4. Запустить API

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```

Документация Swagger: http://127.0.0.1:8000/docs  
Проверка состояния: http://127.0.0.1:8000/health

### 5. Задать вопрос

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"Как продлить срок выдачи книги?"}'
```

Пример формы ответа (конкретный текст и score зависят от модели и индекса):

```json
{
  "answer": "Согласно документу «library_faq.md»: ...",
  "sources": [
    {"file": "library_faq.md", "chunk_id": 0, "score": 0.73}
  ],
  "model_version": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
}
```

Для проверки отказа задайте вопрос, которого нет в корпусе, например:

```bash
curl -X POST http://127.0.0.1:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"Как оформить ипотеку на Марсе?"}'
```

Ожидаемая форма ответа при отсутствии чанков выше порога:

```json
{
  "answer": "Не нашёл информации по вашему вопросу",
  "sources": [],
  "model_version": "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
}
```

## Как работает RAG

1. `scripts/build_index.py` читает документы из `data/`.
2. `chunker.py` делит документы на окна по 320 токенов с перекрытием 48 токенов (15%). Один и тот же модуль используется и для вопроса в API.
3. Одна и та же SentenceTransformer-модель строит эмбеддинги и документов, и вопроса.
4. ChromaDB ищет до двух ближайших чанков по косинусному расстоянию.
5. Расстояние преобразуется в сходство как `1 - distance`; чанки ниже `SIMILARITY_THRESHOLD` отбрасываются.
6. Ответ — только текст найденных чанков с указанием файлов. Генеративная модель не используется, поэтому сервис не дополняет источники вымышленными фактами.
7. В `sources` возвращаются имя файла, номер чанка и score; в `model_version` — имя модели.

## Настройки

Переменные окружения (необязательны):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MODEL_NAME` | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | Одна модель для индекса и запросов |
| `CHUNK_SIZE` | `320` | Размер чанка в токенах |
| `CHUNK_OVERLAP` | `48` | Перекрытие в токенах (15%) |
| `TOP_K` | `2` | Максимальное число источников |
| `SIMILARITY_THRESHOLD` | `0.35` | Минимальное сходство |
| `CHROMA_DIR` | `.chroma/` в проекте | Путь к базе ChromaDB |
| `CHROMA_COLLECTION` | `lab01_documents` | Имя коллекции |

Порог сходства — настраиваемая эвристика, а не универсальная оценка качества. Его можно подстроить под собственный корпус, проверив релевантные и нерелевантные вопросы.

## Ограничения

- В учебной версии индексируются `.txt` и `.md`; PDF-парсеры присутствуют в зависимостях, но обработчик PDF намеренно не включён в базовый индексатор.
- Качество зависит от корпуса, модели и порога сходства.
- Ответ не является свободной генерацией: это извлечённые фрагменты с минимальным шаблоном.
- Индекс `.chroma/` создаётся локально и исключён из Git. Для восстановления достаточно повторить команду построения индекса.
